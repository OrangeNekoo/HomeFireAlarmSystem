# 家庭火灾报警系统

基于 TI CC2530（ZB2530 开发板 ×3）的无线传感网课程设计：三个节点组成家庭火灾监测网络，主节点通过 USB 串口桥接 PC，浏览器打开原神风格网页上位机，实时查看温湿度与有害气体数据、下发阈值、触发模拟报警，报警时三端 LED + OLED 联动。

- 平台：CC2530，IAR 8.10，裸机 RF 直连（不用 Z-Stack），自定义帧协议
- 上位机：纯 HTML/CSS/JS + Three.js，`bridge.py` 做串口-WebSocket 桥
- 课程：无线传感网技术课程设计

## 1. 系统架构

```
[温湿度节点 0x02]──RF──┐
                        ├──→ [主节点 0x01] ──USB串口(CSV)──→ [bridge.py] ──WebSocket──→ [网页上位机]
[气体节点 0x03]──RF────┘     LED+OLED报警                    pyserial+WS+静态托管   localhost:8080
```

- RF：250kbps、信道 11（2405MHz，`FREQCTRL=0x0B`）、16 位 PANID + 短地址过滤、广播地址 0xFF；帧尾异或校验防错
- 串口：USART0，115200 8N1，CSV 文本行 + `*校验` 帧尾
- 上位机链路：`bridge.py` HTTP 静态托管 **8080** 端口，WebSocket **8081** 端口
- 报警逻辑集中在主节点：温度 > 阈值（默认 45℃）或气体 ADC 均值 > 阈值（默认 600）即报警，带回差防抖；主节点广播报警状态，终端 OLED 切`火灾警报`（反显+闪烁）+ LED1 闪烁
- 心跳即数据上报（2 秒周期），超 10 秒未收到判定离线；主节点按序号统计丢包率

完整设计见 [docs/superpowers/specs/2026-09-08-home-fire-alarm-design.md](docs/superpowers/specs/2026-09-08-home-fire-alarm-design.md)。

## 2. 硬件清单与接线

| 器件 | 数量 | 用途 |
|---|---|---|
| ZB2530 开发板（CC2530 核心板 + 底板） | 3 | 主节点 / 温湿度节点 / 气体节点 |
| 0.96 寸 OLED（SSD1306，I2C 模式，BS[2:0]=010） | 3 | 三节点显示 |
| DHT11 温湿度传感器 | 1 | 温湿度节点 |
| MQ-2 烟雾/可燃气体模块 | 1 | 气体节点 |
| USB 线（板载 USB 转串口） | 1 | 主节点接 PC |

### 接线表

三节点 OLED 接线统一（软件 I2C，从地址 0x3C 即写地址 0x78）：

| OLED 引脚 | CC2530 | 说明 |
|---|---|---|
| SCL（D0） | P1.2 | 软件 I2C 时钟，推挽输出 |
| SDA（D1+D2） | P1.3 | 软件 I2C 数据，靠模块板载 4.7k 上拉 |
| VCC / GND | 3V3 / GND | |

其余外设：

| 节点 | 外设 | 引脚 | 说明 |
|---|---|---|---|
| 主节点 | 报警 LED | P0.5 输出 | 低电平点亮 |
| 主节点 | 串口 | P0.2(RX)/P0.3(TX) | 底板 USB 转串口 |
| 温湿度节点 | DHT11 DATA | P0.7 | 单总线，VCC/GND 按模块标注 |
| 气体节点 | MQ-2 AO | P0.6（AIN6） | ADC 采样 |
| 气体节点 | MQ-2 DO | P0.5 输入 | 开关量（超模块电位器设定值为低） |
| 终端 ×2 | 核心板 LED1 | P1.0 输出 | 报警联动闪烁 |

> **MQ-2 供电安全检查**：若 MQ-2 模块用 5V 供电，AO 输出电压可能超过 CC2530 的 3.3V 耐压。首次使用前先用万用表测清洁空气下的 AO 电压，若超过 3.3V，请在 AO 与 P0.6 之间加 10k/20k 电阻分压。

## 3. 烧录步骤

1. IAR 打开根目录工作区 `HomeFireAlarmSystem.eww`，内含三个工程：`Master`、`TempNode`、`GasNode`。
2. 在 Workspace 下拉框切换工程，分别编译（Project → Rebuild All）。
3. 用 USB 线连接目标板，Project → **Download and Debug**（或 Ctrl+D）烧录，烧完复位运行：
   - `Master` → 主节点（接 PC 的那块）
   - `TempNode` → 温湿度节点
   - `GasNode` → 气体节点

三块板固件独立，互不通用，注意别烧错板子。

## 4. 启动步骤

1. **MQ-2 预热**：给气体节点上电预热——首次使用 24-48 小时最理想，演示前至少预热 **5 分钟**（否则读数漂移可能误报）。
2. **主节点接 PC**，确认设备管理器里出现串口（如 `COM3`）。
3. **启动桥**（项目自带便携 Python 3.11，不依赖系统 Python；首次使用先装依赖）：

   ```bat
   Python311\python.exe -m pip install pyserial websockets
   Python311\python.exe bridge.py COM3
   ```

   不带参数运行 `bridge.py` 会自动列出可用串口，方便查找 COM 号。
4. **打开上位机**：Edge/Chrome 访问 <http://localhost:8080>。网页自动连接 WebSocket 并自动对时（三块 OLED 的时钟与网页时间一致）。
5. 正常状态：网页显示三张节点卡片、实时温湿度/气体数值与曲线、丢包率；左上串口状态为已连接。若网页连不上硬件，会自动进入**演示模式**（页面有角标提示），重连成功后自动恢复真实数据。

## 5. 答辩演示剧本

前置：三块板烧录最终固件、气体节点预热 ≥5 分钟、主节点 USB 接 PC、`bridge.py` 已启动、网页已打开。

| 步骤 | 操作 | 预期现象 |
|---|---|---|
| 1 正常监测 | 静置观察 | 三卡片在线（金边），数值与曲线滚动，三块 OLED 显示日期时间与数据 |
| 2 阈值报警 | 网页底部"下发阈值"把温度阈值改为 **30**，对着 DHT11 哈气或用热风加热 | 温度超 30 → 三端联动：主节点 LED 闪烁、三块 OLED 切`火灾警报`（反显+闪烁）、网页全屏扩散反应特效；温度回落后**自动解除** |
| 3 模拟报警 | 点网页"模拟报警"按钮 | 三端真实联动，与真实报警效果一致，按钮切换为"解除模拟" |
| 4 解除 | 点"解除模拟"按钮 | 三端恢复正常界面 |
| 5 离线检测 | 拔掉任一终端电源 | 约 10 秒后网页对应卡片变灰"离线"，主节点 OLED 对应数据行显示`离线`；重新上电自动恢复 |
| 6 断线恢复 | 拔主节点 USB（断开串口） | 网页进演示模式并角标提示；重新插回并重启 `bridge.py` 后自动恢复真实数据 |

演示完记得把温度阈值改回默认（45℃）。

## 6. 常见问题（FAQ）

**串口打开失败 / 被占用**
关掉所有正在占用串口的程序（串口助手、其他 bridge 实例、IAR 的 Terminal I/O），再重新运行 `bridge.py`。

**网页打不开 / 连不上**
- 确认 `bridge.py` 在运行，且用 <http://localhost:8080> 访问（HTTP 8080，WS 8081）；
- 检查 Windows 防火墙是否拦截了 Python，首次运行允许其通过专用网络；
- 端口被占用时换端口或结束占用进程后重启 `bridge.py`。

**RF 收不到数据 / 全部离线**
三块板射频参数必须一致：信道 11（`FREQCTRL=0x0B`，2405MHz）、相同 PANID。检查各板天线是否焊好、节点间距不要太远、主板与终端的 PANID/地址配置是否一致（见 `Common/rf.c` 与各 `main.c`）。

**OLED 全黑 / 不亮**
- I2C 从地址问题：依次尝试写地址 0x78 / 0x7A；
- 软件 I2C 降速（加大 SCL 延时）；
- 确认模块 BS 电阻配置为 I2C 模式（BS[2:0]=010）；
- 确认 SDA/SCL 接 P1.3/P1.2，模块 VCC 接 3V3。

**汉字乱码 / 花屏**
字模为纵向取模、每字 32 字节（上/下半页各 16），来源根目录 `font matrix.txt`；若方向颠倒则整体按位翻转。对照设计规格第 4 节排查。
