# 家庭火灾报警系统设计规格

- 日期：2026-09-08
- 课程：无线传感网技术课程设计
- 平台：TI CC2530（ZB2530 开发板 ×3）、IAR 8.10、裸机（不用 Z-Stack）
- 状态：已与用户对齐，待审查

## 1. 项目概述

基于 ZigBee 射频硬件（裸机 RF 直连，自定义帧协议）的三个节点家庭火灾监测系统：

1. **主节点（协调器，ID=0x01）**：收集两个终端的温湿度与有害气体数据，OLED 汉字显示日期时间、温度、湿度、有害气体状态；超阈值时 LED（P0.5，低电平点亮）闪烁报警；通过 USB 串口连接 PC 上位机。
2. **温湿度节点（终端，ID=0x02）**：DHT11（DATA=P0.7）采集温湿度，OLED 显示日期时间与温湿度，定时上报。
3. **有害气体节点（终端，ID=0x03）**：MQ-2 采集可燃气体（AO=P0.6 ADC 采样、DO=P0.5 数字输入），OLED 显示日期时间与气体状态，定时上报。

### 进阶功能（用户选定范围）

- 主节点串口上报 + **原神风格网页上位机**：实时数据、节点在线状态、阈值设定、模拟报警（下发指令触发真实硬件联动）、Three.js 元素反应 3D 特效
- 网络对时：上位机连接时把 PC 时间下发主节点，主节点定期无线广播对时（三个节点时间自动同步，无需按键）
- 节点掉线检测：心跳超时判定离线，主节点 OLED 与上位机同步提示；统计丢包率
- 终端报警联动：主节点广播报警状态，终端 OLED 切警报显示 + 核心板 LED1（P1.0）闪烁（满足任务书"终端与协调器同时报警"，无蜂鸣器，用 LED 替代声音报警，已与用户确认）

## 2. 系统架构

```
[温湿度节点 0x02]──RF──┐
                        ├──→ [主节点 0x01] ──USB串口(CSV)──→ [bridge.py] ──WebSocket──→ [网页上位机]
[气体节点 0x03]──RF────┘     LED+OLED报警                    pyserial+WS+静态托管   localhost:8080
```

- RF：250kbps、信道 11（2405MHz）、16 位 PANID+短地址过滤、广播地址 0xFF
- 串口：USART0，P0.2(RX)/P0.3(TX)，115200 8N1
- 上位机链路：`bridge.py` 双线程（串口↔WS 转发），HTTP 静态服务 8080 端口，WS 8081 端口

## 3. 硬件与引脚分配

三个节点统一 OLED 接线（沿用示例代码）：

| OLED 引脚 | CC2530 |
|---|---|
| SCL（D0） | P1.2 |
| SDA（D1） | P1.3 |
| RST | P1.7 |
| DC | P0.0 |

| 节点 | 外设 | 引脚 | 说明 |
|---|---|---|---|
| 主节点 | 报警 LED | P0.5 输出 | 低电平点亮（控制 LED 负极） |
| 主节点 | 串口 | P0.2/P0.3 | 底板 USB 转串口 |
| 温湿度节点 | DHT11 DATA | P0.7 | 单总线，读取时需关中断保证时序 |
| 气体节点 | MQ-2 AO | P0.6（AIN6） | ADC 采样，8 点滑动平均滤波 |
| 气体节点 | MQ-2 DO | P0.5 输入 | 开关量（浓度超模块电位器设定值为低） |
| 终端 ×2 | 核心板 LED1 | P1.0 输出 | 报警联动闪烁 |

时钟：32MHz 晶振。时基：T1 定时器 1ms 中断，软计数生成秒级时基与软件 RTC。

## 4. 显示设计与字库

- OLED：SSD1306 0.96 寸 128×64，页寻址，软件模拟 SPI，驱动移植自 `docs/OLED资料/LCD_OLED示例代码`（`LCD.h`/`codetab.h`）
- ASCII 字库沿用 F6x8/F8X16；汉字 16×16 取模来源：用户提供的 `font matrix.txt`（17 字，已含全部所需汉字）
- 字模格式：纵向取模、每字 32 字节（上半页 16 + 下半页 16），与 `LCD_P16x16Ch(x,y,N)` 索引显示方式配套；方向（D0/D7 上下）实现时上屏验证一次，不对则整体翻转
- 字模索引：0温 1湿 2度 3有 4害 5气 6体 7正 8异 9常 10火 11灾 12警 13报 14离 15线 16℃

### 各节点 OLED 界面（128×64，四行）

**主节点**（16×16 汉字 + 8×16 ASCII）：

```
2026:09:08 16:30      ← 行0：软件 RTC，年:月:日 时:分
温度:25℃              ← 行2
湿度:60%              ← 行4
有害气体:正常          ← 行6（正常/异常）
```

**温湿度节点**：

```
2026:09:08 16:30
温度:25℃
湿度:60%
（行6 空或显示节点名 ASCII）
```

**气体节点**：

```
2026:09:08 16:30
有害气体:正常
（浓度数值以 ASCII 显示，如 A:812）
```

- 某终端离线时，主节点对应数据行显示`离线`（汉字）
- 报警时（三个节点一致）：OLED 切换为居中大字`火灾警报`（4 个 16×16 汉字一行居中，x=32 起）+ 整屏反显（SSD1306 0xA7）+ 1Hz 闪烁；解除恢复原界面

## 5. RF 通信协议

### 帧格式（自定义，AUTOCRC 由硬件处理）

```
| 帧头 0xAA 0xBB | 源ID | 目标ID | 命令字 | 数据长度 n | 数据域 n 字节 | 校验和（前 5+n 字节异或） |
```

节点 ID：0x01 主节点、0x02 温湿度节点、0x03 气体节点、0xFF 广播。

### 命令字

| 命令 | 方向 | 数据域 | 周期/触发 |
|---|---|---|---|
| 0x01 数据上报 | 终端→主 | 温湿度节点：温度整数、温度小数、湿度整数、湿度小数（4B）；气体节点：ADC 值 2B（大端）、DO 状态 1B | 2 秒 |
| 0x02 对时广播 | 主→0xFF | 年-2000、月、日、时、分、秒（6B） | 每分钟；串口收到对时后立即广播一次 |
| 0x03 报警状态广播 | 主→0xFF | 状态 1B（bit0=报警中）、报警源 1B（0无/1温度/2气体/3模拟） | 状态变化时 |
| 0x04 模拟报警 | 主→0xFF | 1B（1=触发，0=解除） | 上位机指令转发 |

- 心跳即数据上报：主节点维护每终端"最近收到时间"，超过 **10 秒**判定离线，恢复收到即上线（状态变化时更新 OLED、上报串口）
- 不做重传；主节点按序号统计丢包率并上报上位机（数据域含 1B 序号，见下方修订）

> 修订：0x01 数据域末尾追加 1B 序号（终端自增），即温湿度 5B、气体 4B。主节点按序号跳变数/应收数估算丢包率，随串口上报。

## 6. 报警逻辑（集中在主节点）

- 判决条件（任一满足即报警，带回差防抖：触发阈值与解除阈值相差 5%）：
  - 温度 > 阈值（默认 45℃）
  - 气体 ADC 均值 > 阈值（默认 600，实施时用酒精气体现场标定修正）
- 报警动作：主节点 LED（P0.5）500ms 翻转闪烁 + OLED 切`火灾警报`界面 + 无线广播 0x03
- 终端收到 0x03：OLED 切`火灾警报`界面（反显+闪烁）+ LED1（P1.0）闪烁；收到解除恢复正常
- 解除：实测值低于解除阈值自动解除；模拟报警由指令解除
- 阈值存 RAM，上位机可随时修改（掉电恢复默认值，可接受）

## 7. 串口协议（主节点 ↔ bridge.py，CSV 文本行）

- 帧尾 `*校验`（数据域异或的两位 HEX）+ `\n`，115200 8N1

上行（主节点→PC）：

| 消息 | 格式示例 | 说明 |
|---|---|---|
| 数据 | `D,2,25,0,61,0,345,*7A` | 类型,节点ID,字段…（温湿度=整数/小数各1B；气体=ADC值,DO） |
| 节点状态 | `S,2,ONLINE` / `S,3,OFFLINE` | |
| 报警状态 | `A,1,2` | 报警中,报警源（0无/1温度/2气体/3模拟） |
| 丢包率 | `L,2,3,128` | 节点2丢3包/应收128 |
| 阈值回显 | `T,45,600` | 当前阈值（启动时与修改后上报） |

下行（PC→主节点）：

| 消息 | 格式示例 | 说明 |
|---|---|---|
| 设阈值 | `SET,50,700,*XX` | 温度阈值,气体阈值 |
| 模拟报警 | `TEST,1` / `TEST,0` | 触发/解除 |
| 对时 | `TIME,26,9,8,16,30,0,*XX` | 年-2000…秒；主节点更新 RTC 并立即无线广播对时 |

## 8. bridge.py（Python 桥）

- 运行环境：项目内便携 Python 3.11（`Python311\python.exe`，不依赖系统 Python）；依赖 `pyserial`、`websockets`，用 `Python311\python.exe -m pip install pyserial websockets` 安装
- 结构：双线程——串口读线程逐行解析（校验失败丢弃）→ JSON → `asyncio` WS 广播；WS 收到的指令→CSV→串口写
- 静态托管：`http.server` 于 8080 端口服务 `web/` 目录；WS 于 8081
- 启动：`Python311\python.exe bridge.py [COM口]`；无参数时自动枚举串口打印列表提示
- 上行数据额外打时间戳（桥端接收时刻，供网页曲线用）

## 9. 网页上位机（原神风格）

- 技术栈：纯 HTML/CSS/JS + Three.js（CDN），无构建工具；单页应用
- WebSocket 连 `ws://localhost:8081`；断线自动重连；**连不上时自动进入演示模式**（前端自生成仿真数据与随机报警，便于无硬件开发调试界面，页面角标注明"演示模式"）

### 元素映射与特效

| 物理量 | 元素 | 特效 |
|---|---|---|
| 温度 | 火 | 暖色粒子，温度越高越密集炽红 |
| 湿度 | 水 | 蓝色水粒子环绕流动 |
| 有害气体 | 风 | 绿色风旋涡粒子/流线，浓度越高越急速 |
| 报警 | **扩散反应（火+风）** | 全屏风旋卷火焰爆发冲击波，UI 转入警报态 |

### 视觉规范

- 配色：深蓝夜空底（#0b1c3f 系）+ 米金色 UI（#ece5d8）+ 金色描边（#d3bc8e）；元素色 火#ef7938 / 水#4cc2f1 / 风#74c2a8
- 字体：思源宋体/Noto Serif SC（CDN），标题衬线感
- UI 语言：切角棱形卡片、星芒装饰线、原神式按钮（金边、按下微光）

### 布局（全屏浏览器）

- 中央：Three.js 3D 元素核心晶体（可鼠标拖拽旋转），三色粒子环绕，数据驱动粒子参数
- 左侧：三张节点卡片（协调器/温湿度节点/气体节点）——在线金边亮起、离线灰暗，含各自实时数据
- 右侧：数据面板——三要素数值 + canvas 自绘迷你实时曲线（最近 60 点）
- 底部控制台：阈值设定（温度℃、气体 ADC 值，输入+下发）、模拟报警/解除按钮、报警状态横幅
- 顶栏：系统标题、日期时间、串口连接状态、丢包率、运行时长

## 11. 测试计划

1. **单元/分段**：OLED 汉字上屏（验证字模方向）→ DHT11 读数（串口打印）→ ADC 采样+滤波 → RF 两节点点对点收发 → CSV 串口协议（串口助手）
2. **集成**：三节点组网（对时/上报/离线判定/报警联动）→ bridge.py → 网页数据流
3. **场景**：正常数据展示；打火机/酒精逼近 MQ-2 触发气体报警；热源触发温度报警；上位机改阈值；模拟报警触发与解除；拔掉终端电源验证离线提示；网页断线重连与演示模式
4. 验收对照任务书：协调器 OLED 四行显示、汉字、LED 报警、终端显示与联动

## 12. 风险与备选

| 风险 | 对策 |
|---|---|
| DHT11 时序与 RF 中断冲突（读数 4ms 关中断） | 读数期间丢包可接受（2s 周期）；实测丢包率异常则将 DHT11 读取错开对时广播时刻 |
| MQ-2 需预热（首次通电 24-48h 理想，演示前至少预热 5-10 分钟） | 演示流程注明提前上电预热；上电前 60s 显示"预热中"（ASCII）不参与报警 |
| 字模方向不符（D0/D7 颠倒） | 整体按位翻转或重新取模，验证成本低 |
| ADC 阈值标定困难 | 以 DO 触发时刻的 AO 读数为准现场标定；上位机可改阈值 |
| 裸机 RF 收发可靠性 | 固定信道+异或校验+高频上报弥补；AUTOCRC 开启 |
